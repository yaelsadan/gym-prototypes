Student Practice Rooms — Mobile v6 · header: status vs chrome

The first mobile Practice Rooms surface. Behaviour is taken wholesale from the Desktop v21 checkpoint — teacher-triggered activities, the 5s prep countdown, the Dialogue / Intensive / Operation Grandma / Carousel recipes, the fill-forward timer with its coral final seconds, the routing matrix, the one-source-of-truth room clock and the matkot transition fix. The layout is not ported: the Duo Room is a vertical stack, the activity zone lives on the seam between the two tiles (which is exactly where neither face is), popups are bottom sheets, and the controls sit in the thumb zone. Tokens, the phone shell, the statusbar, the header and the sheet language come from the mobile system reference.

v4 — transition typography + auto-hide chrome

  • The transition headline is FedraSerifPro, embedded from the same licensed base64 as the desktop checkpoint. It is the only thing in the file on the brand serif — the supporting copy, the muted pill, the waiting countdown, the chips, the controls and the room timer all stay on Assistant. Git-safe export: strip the @font-face and repoint --font-brand to Georgia.
  • Auto-hide chrome. On room entry the chrome shows for 3s, then fades out over 200ms if nothing is touched. A tap anywhere on the video brings it back for 3.8s. Tapping a control resets the timer rather than hiding — the header and footer bump it on any tap inside them. No hover anywhere.
  • Opacity only. No display:none, no height change, no reflow — the video cannot jump. Hidden chrome carries pointer-events:none so it never swallows a tap. The class is toggled on #screen; the room is never re-rendered to hide chrome, so the START chip and the Carousel loader are not restarted.
  • What hides: the close X, the expanded room context, the TIP / Camera / Mic controls, Leave & report, and the footer scrim. The header scrim only dims to 50%, because the room timer and the partner chip sit on it.
  • What never hides: the room timer, the name chips (they are identity and turn state — You / Dana / Your turn / Dana’s turn / You start / Dana is next), the START chip, the active-turn yellow frame, the activity timer, the 5s countdown, the prepared pill, the Carousel cue and the Done badge. Those are asserted explicitly in CSS so a future pass cannot sweep them into the chrome rules.
  • Blocking surfaces pin the chrome open: the consent sheet, the camera/mic warning, the partner-left sheet, Leave & report, the TIP player, the report screen, the waiting / return screen and the Solo room. The auto-hide timer is never armed while one of them is up.

Mobile-native decisions (not on desktop)

  • Vertical stacked Duo split. Partner on top, you on the bottom — closest to your thumb. No two-column assumption survives the port.
  • The seam is the activity zone. Portraits put the faces at roughly y 208 (partner) and y 624 (you). The seam band runs y 360–478 — precisely between them. The 5s countdown, the timer, the prepared pill, the Carousel cue and the Done badge all live there, so none of them ever covers a face.
  • One timer position. Desktop attaches the timer to a tile corner for Grandma and Carousel; on a 378px-wide phone that crowds. Mobile keeps one timer, on the seam, for every activity.
  • Carousel collision rule. When Carousel runs, the seam becomes a flex row: timer (112px) + gap (22px) + cue (116px) = 250px inside a 378px screen. Both are fully visible, neither overlaps, and both stay in the face-free band.
  • Popups are bottom sheets (consent, camera/mic, partner-left, Leave & report) — thumb-reachable, not centred modals.
  • Name chips hug the outer edges of the stack: the partner’s under the header, yours below the seam. The START chip sits under each name chip and fades in ~0.95s.
  • Controls in the thumb zone: TIP · Camera · Mic as 58px targets, with Leave & report as a lighter ghost pill beneath them.

Carried over from Desktop v21 (unchanged behaviour)

  • Teacher-triggered activities. Selecting an activity only prepares it. The timer starts on the simulated Cockpit Start timer event.
  • 5s prep countdown, with the yellow frame on from the first tick. Dialogue 5/20/5/20 · Intensive 5/10/5/10 · Grandma runs a full set automatically (prep → R1 → R1 → 5s break → R2 → R2) · Carousel 5/20/5/20 with the cue switching every 5s.
  • The timer is the v21 component, byte-for-byte in geometry: fill-forward (charcoal track → yellow → coral in the last 5s), one stroke weight of 1.4, ball fill r 4.6 painted last so the arc endpoint can never be exposed, rAF-interpolated so the arc and ball never jump. Sized 112px for mobile.
  • Turn state: yellow frame + “Your turn” / “Dana’s turn” chip. Never “Speaking”. Yellow = current turn, not speech detection. No green anywhere.
  • Routing matrix: consent decline, own camera/mic off, leave room, report submit/skip → waiting / return, never Solo. Partner left / unavailable, and uneven students → Solo.
  • One room clock. ST.roomLeft feeds the header and the waiting screen, keeps ticking while you wait, goes yellow in the final 10s, and returns you to the Main Room at 00:00.
  • The matkot fix: the ball carries a charcoal stroke, and the room clock never re-renders the frame — it writes the countdown in place, so the Lottie is never destroyed and reloaded. No scratched-disc loop.
  • Not in rooms: no chat, no reactions, no participant rail, no written prompts.
